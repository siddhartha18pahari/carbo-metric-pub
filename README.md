# Carbo Metrics

Per-pixel D and G band fitting of Raman maps of carbons, with maps of every band, their ratio and the fit error. It follows the conventions of the Q-Carbon module of HORIBA LabSpec 6 (same panel layout, configuration and export), and adds views Q-Carbon does not have: a registered white-light overlay, linked cursors, particle-level statistics, spectral Gaussian splatting and a printable report.

**Web app:** https://carbo-metrics.vercel.app. It runs entirely in your browser: files are read on your computer and never uploaded.

## What it opens

- LabSpec 6 binary maps (`.l6m`), read directly with no export step, plus the white-light image saved with them (`.l6v`). Maps recorded through the laser line (spectra starting in the anti-Stokes region, e.g. −1130 to 1940 cm⁻¹) are read too.
- LabSpec ParticleFinder projects (`.l6pf`): one spectrum per particle, with each particle's stage position, size and shape and the mosaic camera image. A ParticleFinder spectra list (`.l6m` with no grid) opens with the `.l6pf` saved beside it (in the web app, drop both together).
- Text exports from any instrument (`.txt`, `.csv`, `.tsv`, `.dat`; tab, comma, semicolon or space separated, decimal commas allowed):
  - a LabSpec matrix export (first row = Raman shift, then one row per point). A map whose acquisition stopped early (e.g. 118 of an 11 × 11 grid) opens on its grid, with the points never measured left out of the fit and the statistics;
  - an x / y / shift / intensity table (e.g. Renishaw WiRE);
  - a two-column spectrum (shift, intensity), shown as a single point.
- Fitted-result tables: Q-Carbon's own *Export data* `.txt` (per point: D/G intensity, width, area and ratios) and this app's *Export all (CSV)*. They hold fitted values and no spectra, so they open as maps, histograms, statistics, particles and a report, with nothing to refit. Q-Carbon's export carries only the two bands of its ratio (G and D3, or D1 and G: all 61 exports checked) and no standard error, so the other bands and the Error map need the map itself; the app says so and offers to fit the `.l6m` (one click when it was opened with the export). The spectral Processing settings are greyed out for the same reason; *Smoothing (spatial)* still works, on the fitted maps. The cursor spectrum and the Spectral data panel draw the bands the values describe: each band at its exported height and width, with the line shape read off the exported areas (area / (height × width) is 1.06 for a Gaussian, 1.3 or more for a Lorentzian cut to the fit range) and no baseline. Q-Carbon exports no band positions, so those bands sit at their configured positions and the plot says so. Q-Carbon's export has no coordinates: open it together with its `.l6m` (and `.l6v`) to use the real grid and white-light image. Opened alone, its grid is inferred from the point count, choosing the most isotropic map with a mild preference for square shapes. On 34 exports with a same-size `.l6m` on disk the first choice was right 33 times. The Spectral data panel lets you pick another grid.

Older 32-bit LabSpec files, scattered points that share no grid, and spectra lists without their ParticleFinder project are refused with a message rather than guessed at.

## Two ways to run it

**In the browser.** Open the web app and click **Open file…** (or drop a file onto the window). Pick the `.l6m` and its `.l6v` together to get the optical overlay. The fit runs in Web Workers on your machine.

**On your computer** (faster numba engine, a library of your data folders, and Splat 3D):

```
pip install -r requirements.txt
python run.py
```

It opens at http://127.0.0.1:8765. On Windows you can double-click `Carbo Metrics.bat`. To list your own data folders in the library, copy `data_roots.example.txt` to `data_roots.txt` and add one folder per line. Splat 3D also needs `ramansp` (`pip install git+https://github.com/siddhartha18pahari/RAMANSP`).

Both run the same engine: `web/js/engine` is a port of `qcarbon/fitter.py`, and a test holds the two to the same numbers (to 1e-7).

## Same as Q-Carbon

| Q-Carbon | Here |
|---|---|
| Processing: baseline (poly order), Fit separately, spectral range | same. *Fit separately* = modified-polynomial baseline first, then the bands |
| Constraints: Intensity / Ratio(I) / Ratio(Ar) ranges with tick boxes | same; they decide which points are *valid* |
| Peaks table: Pos/Min/Max, Width/Min/Max, Lorentz/Gauss, Fit, peak names, Skip fitting step | same |
| Configuration open/save, Ratio type (D/G or G/D) | same; saved as this app's own `.ini` |
| D, G, Ratio and Error maps, each switchable to Intensity / Width / Area | same, plus Position, red. χ², iterations and mean counts |
| Cursor spectrum, histogram, white-light image, all spectra | same |
| Quality (total/valid points, std. error, red. χ²), Statistics (mean, SD) | same, plus median and IQR |
| Export data (.txt) | same column order as the vendor export; also a full CSV with X, Y, every band and the valid flag |
| Report / Save as PDF | Report tab, then Print, then Save as PDF |

The default configuration is a typical five-band carbon model: poly order 2 baseline fitted with the bands over 1000–1800 cm⁻¹; G 1580 Lorentz (width 10–35), D1 1350 Lorentz, D2 1620 Lorentz, D3 1500 Gauss (40–200), D4 1200 Lorentz; ratio D3/G. Every value is editable and can be saved.

## Added

- **Shapes from the mean spectrum** (Processing, on by default). See *D3* below.
- **Smoothing, as options** (all off by default, so the fit sees the raw spectra as in Q-Carbon):
  - *Smoothing (spectral)* in Processing: Savitzky–Golay along the Raman shift (5–21 points, order 2–4) before the fit. Spectra look cleaner; fitted values change little, and a wide window broadens narrow bands such as G.
  - *Smoothing (spatial)* in Processing: each spectrum smoothed with its 3 × 3, 5 × 5 or 7 × 7 neighbours on the map (Gaussian weights over measured neighbours) before the fit, so every map follows, Ratio and Error included. Weak-band maps such as D3 get much cleaner (3 × 3 cuts per-pixel noise about 2×), at the cost of resolution. Neighbouring points then share data, so per-point statistics overstate the number of independent points. On a file of fitted values (no spectra) the fitted maps themselves are smoothed and the ratios recomputed. Off for ParticleFinder data, where neighbouring particle numbers are not neighbouring places.
  - *Filter* in each map's ⚙ menu: Gaussian or median, 3 × 3 or 5 × 5, over valid neighbours. Display and PNG only; statistics, histograms and data exports keep the raw per-pixel values.
  - *Smooth / Raw* chip on each map: D1 to D4 are weak bands, noisy pixel to pixel, so their maps are drawn smoothed by default (Gaussian 3 × 3 filter and interpolated pixels); G, the ratios and the error are drawn as measured. One click switches a map between the two, remembered per map and band. Display only, like the filter.
  - With either pre-fit option on, the cursor spectrum shows the smoothed spectrum the fit used, over the raw one, and Std. error and χ²ᵣ describe the smoothed spectra.
- **Registered optical image.** The map is drawn on the `.l6v` white-light frame at its true stage position, with an opacity slider. The crosshair follows the cursor.
- **Linked cursor.** Hovering any map updates all four maps, the spectrum and the optical image. Click to pin a point, and use the arrow keys to step through pixels. The spectrum shows each fitted band, the baseline and the residual. Drag to zoom.
- **Exclude substrate (Otsu).** One click sets the intensity limit so bare substrate stops counting. On one test map the D3/G intensity ratio over all points is 0.37 ± 2.09; on the 3 325 particle points it is 0.060 ± 0.035. Per-pixel ratios on bare substrate are noise divided by noise.
- **Particles tab.** Finds particles (Otsu on log(1 + I_G)) and splits touching ones at the neck with a marker watershed. It reports pixel-level vs particle-level statistics. Neighbouring pixels are not independent samples, so compare samples on particle means.
- **ParticleFinder particles.** Every particle's spectrum is fitted with the same configuration as a map. The maps draw each particle at its stage position, coloured by the fitted value, as an ellipse with the particle's own area, the aspect of its Feret width over its Feret length, and its tilt (see *ParticleFinder format*), with a darker rim so touching particles stay apart. Zoomed in, the optical image draws the same shapes over the mosaic. The maps draw the particles over the camera image, in greyscale so it cannot be mistaken for part of the colour scale (⚙ menu: *Camera image underneath*). With many particles in view, each only a few screen pixels across, the small ones are drawn larger so their colours can be compared: sizes are compressed about a readable size, so the bigger still look bigger, and none is drawn smaller than it is. The note beside the scale bar says when this is on. The Particles tab plots any fitted value against the instrument's morphology (diameter, area, min diameter, convexity, elongation, volume) with binned medians and a rank correlation, as a density of hexagons (light to dark with the number of particles, on a log scale) or one dot per particle, and lists the particles; click one to see its spectrum, or its number to open the D, G, Ratio and Error maps zoomed onto it. *Export all (CSV)* adds position, morphology and class per particle. Splat 3D needs a grid and is off for these files.
- **Semi-quantitative particle results** (Particles tab, ParticleFinder data). Every share comes with a 95 % interval, and every figure uses only the particles whose spectra can carry it:
  - *Uncertainty of each band*: the standard error of every fitted height comes from the particle's own fit, its residual through the fit's covariance (the model linearised at the solution, over the parameters the fit moved). A broad, weak band such as D3 is judged against every channel under it rather than the noise of one channel: on 400 synthetic replicates the predicted errors of D3, G and D3/G agree with the scatter of repeated fits to within 15 %. A band is *detected* when its height is at least 3 standard errors (editable); a particle is *quantified* when G is at least 10 × the residual noise, inside its fit bounds (a band on a bound is fitting noise) and passing the Constraints. Flat (all-zero) spectra count as not measured.
  - *Coating uniformity* (the band of the amorphous coating over G, D3/G by default): if every particle carried the same coating, the values would scatter only by their own errors. Cochran's Q tests that; I² is the share of the spread beyond the errors; the particle-to-particle CV is the SD of the true values (Paule-Mandel, with its Q-profile 95 % interval) over their mean. A verdict (uniform within the measurement, nearly, moderately or strongly non-uniform) comes with the share of particles where the coating band is detected, the share outside the noise band (2.5 % each way if uniform), a drift along the particle order (the order ParticleFinder measures in; removed with a running median before the numbers above, and reported, since laser, focus or background drift would read as non-uniform coating), spatial clustering (Moran's I, 6 nearest neighbours) and the trend with particle size. Plots: a funnel (the coating index against its error, with the band one uniform coating allows), a caterpillar plot (every particle in order of its coating index with its 95 % interval, over the band of the real spread between particles, so the particles that differ beyond their noise stand out), the values along the particle order with their running median, and the deviations in units of their own error against the N(0, 1) curve a uniform coating gives. The map and the mean spectra can show the particles below, within and above the band. On a 4 575-particle project the coating was moderately non-uniform: D3 detected in 35 % of quantified particles, I² 49 %, a particle-to-particle CV of 37 % (35 to 39 %) once a drift of D3/G from 0.047 to 0.019 along the particle order was removed. One spot is measured per particle, so this compares particles; coverage within a particle needs a map of it.
  - *Overview* (the top of *Coating uniformity*, ParticleFinder data and maps alike): the verdict with its status (an icon and words, not colour alone); a meter of the real share of the spread (I²) against the nearly even / moderately / strongly patchy zones; tiles for the mean coating index, the CV with its 95 % interval drawn, and the thinnest 5 % (on maps, the CV between particles); one stacked bar of where the spread comes from (measurement noise, real variation within and between particles, drift); and the distribution of the coating index, measured, against what noise alone would give and the true values with the noise taken out, the thinnest 5 % and the lower limit marked, with a tooltip per bin. On maps, a row per particle shows how patchy it is inside, with its interval, patchy ones apart. The longer explanation folds under *What this means*; every number is still in the cards below. Chart colours were checked for lightness, chroma, colour-blind separation and contrast against each theme's chart surface.
  - *What the run measured*: ParticleFinder keeps a status for every located particle (measured, selected but not measured, excluded by the run's own size or shape filter). Only measured particles enter the results, as in LabSpec's own; the filter-excluded ones can be included with one tick. Objects lying on the seams of a stitched mosaic (the dark borders between camera tiles, which ParticleFinder can take for particles) are left out as well. Both counts show under *Detection and quality*. On a 364-particle project, 281 particles were never measured and 101 objects sat on tile seams. On a 4 575-particle project, the run's filter had excluded 4 165 particles that still carry spectra; the measured 409 give a mean D3/G of 0.058, the excluded ones bring it down to 0.038.
  - *Beyond the CV, between particles*: the Gini coefficient of the coating index against the value noise alone gives (each particle's index replaced by the mean plus its own error), and whether a lognormal fits better than a normal; where it does, a limit belongs on the logarithm or the quantiles, not as a band about the mean. Also measures that need no mean: the quartile coefficient of dispersion (q3 − q1) / (q3 + q1), q90/q10, the share of the total the lowest tenth holds (10 % if even), Shannon evenness over 32 bins, skewness and excess kurtosis.
  - *The thinnest particles*: the particles' true coating index modelled about a mean with each particle's own error taken out (Paule-Mandel random effects; lognormal, on the log scale, when the values are right-skewed). Reported: the 5th percentile of the true values with a 95 % interval from 400 resamples of the particles, a 95 % prediction interval for the next particle's true value (Higgins et al. 2009), and, against a lower limit set under Acceptance, the share of particles below it with its interval and the equivalent Cpk, z(1 − share) / 3 ((mean − limit) / 3 τ for a normal). On a 4 575-particle project: the thinnest 5 % carry D3/G of 0.037 or less (0.034 to 0.041) with the noise taken out, where the measured values alone give 0.022; against a limit of 0.02, 0.0 % below (0.0 to 0.1 %), Cpk 1.2.
  - *Coating against morphology*: least squares of the coating index on diameter (log), convexity and elongation together, each scaled to its standard deviation, with heteroscedasticity-robust (HC3) errors and Holm's adjustment over the three. On the same project, larger and more convex particles carry more coating (Holm p < 0.001 and 0.003), elongation does not matter, and the three explain little of the spread (R² 0.09).
  - *Every spectrum, sorted* (the spectra panel): each quantified particle's spectrum as one row, baseline removed and scaled to its G height, ordered by its coating index from the bottom up, on a square-root colour scale so weak bands show. Rows are averaged when there are more particles than pixel rows. *Minus the median* subtracts the median spectrum, blue below and red above, so what sets particles apart stands out from what they share: on a 4 575-particle project, the most coated rows run above the median across much of the range, not only at D3.
  - *Populations* on a chosen band ratio over G (D1/G by default), the G width and the G position: a Gaussian mixture (lowest ICL of 1 to 4 components), whose components are merged when their density shows no dip between them (ridge ratio above 0.2, Hennig 2010), so one continuous spread stays one population; or cut-offs on the ratio. Particles whose band is below detection form their own *n.d.* group. Shares by number (Wilson) and by ParticleFinder volume (bootstrap over particles; a mass share only at equal density), and a mean spectrum per population, baseline removed and scaled to G.
  - *Crystallite size* L<sub>a</sub> = 2.4 × 10⁻¹⁰ λ⁴ (A<sub>D1</sub>/A<sub>G</sub>)⁻¹ nm (Cançado et al. 2006), with λ = 532 nm by default (the lab's 532 nm edge laser; LabSpec's acquisition record, when it has one, is shown beside it). Values outside the calibrated range (about 2 to 500 nm) are counted, not hidden.
  - *Size*: D10, D50, D90 by number and by volume over the particles measured, off the tile seams and as the run's filter left them, with every object in the table beside them (as the routine's own histogram counts them: on a 4 575-particle project, D50 2.81 µm measured against 1.17 µm over every object); the ratio by diameter quartile, the volume-weighted mean ratio and its rank correlation with diameter; and fixed size classes (< 1, 1–3, 3–10, 10–25, ≥ 25 µm) with the particles located, measured and quantified in each and, once Coverage is set, the share judged coated with its exact lower bound, so that a size limit cannot hide inside a total. *Export particle analysis (CSV)* writes every particle with its signal-to-noise, G height over its error, detection, population, ratio, G width and position, A<sub>D1</sub>/A<sub>G</sub>, L<sub>a</sub>, and its coating index with its error, detection and place against the noise band.
  - *By particle* (Carbon fit tab): the four maps of a particle list can also be drawn as Q-Carbon draws them, each particle's value against its number; the chip on any map switches all four.
- **Coating coverage on maps** (Particles tab, gridded maps, after *Find particles*). ParticleFinder measures one spot per particle; a map of coated particles shows whether the coating covers each particle evenly.
  - *Pixels*: every pixel inside a particle whose G is at least 10 × its noise (inside its fit bounds and the Constraints) carries the coating index (D3/G by default), with its standard error from that pixel's own fit, as for ParticleFinder.
  - *Rim*: pixels within 1 µm of a particle's edge (editable) are left out. The laser spot lies partly off the particle there and G falls. D3/G rises at the rim of an uncoated reference map too (1.9 × the interior, G 0.53 ×), so the rim says little about the coating. The verdict reports the rim against the interior either way.
  - *Within each particle*: Cochran's Q over its pixels, I², and the CV of the true values (Paule-Mandel τ, with its Q-profile 95 % interval, over the mean). The cards pool this over the particles (one τ from the summed Q), the table gives it per particle with the share of pixels where the band is detected (height ≥ 3 SE).
  - *Between particles*: each particle's mean, with the error its pixels give (its noise and its own spread), goes into the same random-effects test, so the real variation splits into a within-particle and a between-particle part. Particle means rest on hundreds of pixels, so I² between them is near 1 for any real difference; the verdict therefore compares the between-particle SD with the within-particle SD.
  - *Pixel pairs*: two pixels of one particle at a given distance differ, on average, by some multiple of what their errors predict (1 if the errors are right and nothing changes). With a step smaller than the spot, the nearest pairs check the errors: errors that are too small give the same excess at every distance. Real patches give a rise with distance. Rows and columns give the same values on the maps checked, so the patches are not a drift during the acquisition.
  - *Map*: each pixel coloured against its own particle's mean: within, above or below the band its error allows (95 %), with the rim in grey.
  - *Errors on the large side*: where the pixels scatter less than their errors predict (Q below its lower 2.5 % point), the Q-profile interval collapses to 0. The plain scatter (noise and real spread together) is then the upper limit quoted.
  - *Particles cut by the map*: the share of each particle's outline that lies on the map's border is listed, and the verdict says when a particle runs off the map. The map's border is not treated as a rim, so a cut particle keeps its pixels there.
  - *Beyond the CV, inside the particles* (each particle with at least 100 pixels; the cards show the median): the Gini coefficient against its noise-only value; the variogram, whose nugget, estimated without the noise model, is compared with the noise the fits predict (0.5 to 2 times counts as agreement, otherwise the noise-corrected numbers should not be relied on), and whose plateau above the nugget is the structured spread; locally thin places by Getis-Ord Gi* (5 x 5 neighbourhood, false discovery rate 5 %), against the same field with whole 8 x 8 pixel blocks moved about, which keeps any structure up to that size, so only the excess is thin regions larger than the blocks; lognormal against normal; and the effective number of independent pixels from the lag-one correlation, n (1 - rho) / (1 + rho). Also QCD, q90/q10, the lowest tenth's share, evenness, skewness and kurtosis; Moran's I and Geary's c against 199 shuffles of the same pixels; and, per particle in the table, the excess CV (robust CV beyond the pixels' own errors) and the percentile uniformity U = (q95 − q5) / (q95 + q5), each with a 95 % interval from 500 resamples of whole 8 × 8 pixel blocks, which keeps neighbours that share their noise or their patch together.
  - *Limits*: neighbouring pixels are not independent. With a 0.25 µm step, a 532 nm spot of about 1 µm covers about 13 pixels. Each spectrum still has its own noise, so the test of one common value holds. Patches smaller than the spot are averaged away, though, and the intervals count the pixels as more independent than they are, so they are too narrow. Smoothing before the fit is refused here: it changes the noise each error is computed from.
  - *Results*:

    | Map | Within-particle CV (I²) | Between particles | Pixel pairs, near to far |

    D3 is detected in 97–98 % of the coated pixels and 30 % of the uncoated ones. Coating index = D3/G with D3's shape held at the mean spectrum, so compare maps fitted the same way.
- **D3/G calibration** (Particles tab, both kinds of data): I(D3)/I(G) with band shapes calibrated once and held for every sample, so the values compare between samples and sessions. The Carbon fit's free per-pixel shapes do not give that.
  - *The calibration* is built in steps. A graphite and a glassy carbon spectrum are fitted in the Q-Carbon windows: G from graphite, D1 to D4 from glassy carbon. Each band's median position and width over the carbon spectra of an uncoated reference map, where the band is at least 3 × the noise (R² above 0.5), gives baseline 1; the same over a coated map, starting from baseline 1, gives baseline 2. A band found in fewer than 5 % of the spectra keeps the step before's shape: in the calibration of 21 Oct 2026, D3 is too weak on both maps, so its shape (1510 cm⁻¹, FWHM 170 cm⁻¹) is glassy carbon's. That calibration ships with the app, baseline 2 selected.
  - *D3 on the uncoated map* (a build option, on by default): no single uncoated spectrum carries D3 (on the 21 Oct uncoated map, 0 of 3 096 reach 3 × noise), so the build can fit D3 on the uncoated map's median spectrum instead, started from glassy carbon's shape. It is taken when its height is at least 3 × that fit's residual (the median of whole counts reads 0 noise by second differences, and the residual is mostly misfit, which a real band must stand above); a position or width on its window limit keeps glassy carbon's value; otherwise glassy carbon's shape stays, and the build says which. On synthetic maps of 400 spectra with D3/G 0.02 (1 × noise per spectrum) the median spectrum puts D3 within about 3 cm⁻¹ of its true position. On a real low-D3 map (D3/G 0.012) the fit gives a narrow band (56 cm⁻¹) on the 1490 limit at 1.7 × the residual, a shoulder rather than a coating's broad D3, and glassy carbon's shape is kept. The shipped 21 Oct calibration was made by the calibration's scripts without this option.
  - *Build a calibration* makes one from your own four files (the standards as LabSpec `.l6s` or two-column text spectra, the maps open in the window); *Save calibration* and *Load calibration…* keep it as JSON. The calibration scripts' own `baselines_D3G.json` reads too (its values are rounded to 0.01 cm⁻¹).
  - *Applied*: each spectrum is cut to 1000–1800 cm⁻¹ and cleared of cosmic rays (points more than 8 × the noise above a 7-point running median, at most 2 points wide). Its noise is the robust SD of the second difference over √6, and it counts as carbon when its smoothed G (1540–1630 cm⁻¹) stands at least 10 × that above a straight line through the two ends of the range. On carbon spectra the five heights (0 to 5000 counts) and a poly-2 background are solved by bounded least squares with every position and width held. Reported: the median I(D3)/I(G) with a 95 % interval from resampling whole blocks (8 × 8 pixels, or 150 µm squares of particles, since neighbouring map spectra share their signal), A(D3)/A(G) from the line shapes' own areas, D3's height over its error, and the residual over the noise (flagged above 2). ParticleFinder data use the particles the rest of the tab uses (measured, off the seams).
  - *Against an uncoated reference* (open in the window, or read from disk with *Choose a file…*, see Coverage), or its median entered by hand: the difference of medians with its block-resampled interval, and their ratio. Signal-to-noise differing by more than 2 × between the two is flagged: noise raises I(D3)/I(G), since a height cannot go below zero.
  - *Uncoated 0 → glassy carbon 1*: where the sample's median sits between the uncoated reference and glassy carbon, the amorphous reference, (R − R_uncoated) / (R_glassy − R_uncoated), with glassy carbon's I(D3)/I(G) taken from its standard spectrum with the same held shapes (0.391 with the 21 Oct baseline 2; the calibration scripts' own fit gives the same to 1e-14), and a 95 % interval from the same block resamples. A sample of the 21 Oct calibration sits at 0.085 (0.081 to 0.092). It places D3/G between the two references; it is not a mass or thickness fraction. With baseline 1's narrow D1 and D2, glassy carbon reads 0, and no scale is given. The export carries the scale per spectrum.
  - *Check: shapes from this file* fits the file's spectra freely from the shapes in use and takes their median shapes, then reports how far I(D3)/I(G) moves, the residual, and where G sits against the calibration (a shifted G points at the instrument's calibration, silicon at 520.7 cm⁻¹). The result above keeps the calibration's shapes.
  - *Export (CSV)*: every spectrum with its signal-to-noise, the five heights and their errors, the ratios and the residual. *Show on the map* draws the calibrated ratio.
  - *Checked against the calibration's own scripts* (`tests/test_d3g_package.py`). On their 177-particle ParticleFinder sample, every particle's I(D3)/I(G), A(D3)/A(G), error and signal-to-noise agree to 1e-9, and so does the median (0.0559). The standards give the scripts' first-step shapes to 0.1 cm⁻¹. That sample's own median shapes come out within 0.1 cm⁻¹, with the same band counts. The differences of medians between the scripts' three samples are identical, and their 95 % intervals agree to resampling error (uncoated to coated map: +0.029, 0.024 to 0.034). On its uncoated map every pixel's I(D3)/I(G) agrees to 1e-9 too (3 096 carbon pixels, median 0.0248), and baseline 1 rebuilt from the standards matches its positions to 0.1 cm⁻¹ and its widths to 0.75 cm⁻¹ (D1 and D2: this app's Levenberg-Marquardt against the scripts' trust-region fits, over thousands of weak fits). On that map D3 is not found on the median spectrum either (fitted at zero height), so a build keeps glassy carbon's D3. The coated map was not on the test machine, so baseline 2 was not rebuilt there: that test skips.
- **Coverage** (Particles tab, both kinds of data): the share of particles, or of a particle's area, that carries the coating.
  - *Threshold*: tau, from an uncoated reference measured in the same session (or entered by hand): the 99th percentile of its coating index, so 1 % of uncoated spectra pass it. The reference is one of the files open in the window, or *Choose a file…* at the end of the list reads it from disk (a map with its `.l6v`, a ParticleFinder spectra list with its `.l6pf`, or a text export; pick the files together). It opens beside the current file, which stays on screen, and is fitted with the Carbon fit settings, which the threshold is read from. One uncoated reference serves Coverage and the D3/G calibration: read for one, it is taken by the other too where none is chosen yet. The calibration build's uncoated and coated maps can be read the same way.
  - *Signal floor*: a spectrum is judged only if its G is high enough for a coating of the thinnest functional index rc to be found against tau with the chosen power (95 % by default), P = 1 - Phi[(tau - rc) / sigma_R(g)], sigma_R(g) = sqrt(sigma_D² + rc² sigma_G²) / g, from the noise of the band heights. Below it a coated and an uncoated spectrum cannot be told apart, and counting them would measure the signal rather than the coating. Dim spectra scatter more, so the reference's threshold depends on how bright the spectra are that it is taken over: the floor and tau are found together, as the lowest G at which tau, taken over the reference spectra at least that bright, still allows the power. On an uncoated reference map, tau is 0.065 over all quantified spectra but 0.020 over those above 200 counts.
  - *ParticleFinder*: the share of judged particles above tau, with an exact (Clopper-Pearson) 95 % lower bound; the coverage that certifies (a particle is found coated with the detection power when coated and with the false-detection rate when not, so p is certified when the bound reaches p x power + (1 - p) x false detections), and the number of particles that certifies the chosen level. That count is the one from which every larger count certifies: with rounded failures, passing is not monotone just above the first passing count (at 99 % power and 1 % false detections, 99 % first passes at 529 particles but fails again up to 660; 661 is the count).
  - *Maps*: the covered area of each particle above the floor. Its lower bound is the lower of two: an exact bound that counts its pixels as the independent values they are worth, and the 2.5th percentile of the covered share over 500 resamples of whole 8 × 8 pixel blocks. On a coated map, with a reference of the same session and a thinnest coating of D3/G 0.03: floor 183 counts, tau 0.020, 29 % of particle pixels judged, covered area 99 % (lower bounds 93 and 96 %).
  - *Without a threshold* (ParticleFinder): the quantified particles as a mixture of an uncoated and a coated population, each particle with its own error. With an uncoated reference open, the uncoated population is a kernel density of the reference's own values (noise included) and only the coated one is fitted; the uncoated share comes with a 95 % interval from 200 resamples and a likelihood-ratio test against none. Without a reference, two free normal populations are claimed only when the BIC prefers them and they separate (Ashman's D above 2), and the low one is reported as a low group, not as uncoated. A right-skewed coated population would split into a bulk and a tail and pass for two: every model is fitted on the index and on asinh(index / median error), linear near the noise and logarithmic above it, and the scale whose best model has the lower BIC (likelihood carried back by the Jacobian) is kept. On the 4 575-particle project: one population, no low group (separation 0.2), where the linear scale alone would have called 91 % of the particles a low group.
  - *Spectra left out*: a spectrum above the floor whose G or coating band sits on a fit bound, or whose coating band is fitted with zero height, cannot be judged. It is left out and counted: coverage is quoted between the two cases (all of them uncoated, all coated), and the exact lower bound is taken on the first. A band whose shape is held for every spectrum (at the mean spectrum's, or by the user) is not fitted per spectrum, so its shape on a bound does not count.
  - *Noise from*: the noise of the band heights that sets the floor comes from each spectrum's fit by default. On a map it can come instead from differences between neighbouring pixels (robust SD over √2, which errs high, since neighbours also differ by real change); on ParticleFinder data, from the error of a height read without a fit (channel noise and baseline variation, see *Checks*).
- **Checks on the measurement** (Particles tab, both kinds of data).
  - *Band-height noise*: from the fits, against neighbouring pixels on a map (a factor above 2 in the coating band is flagged; G varies from pixel to pixel for real, and its error enters the ratio only times the ratio squared) or, on ParticleFinder data, against a height read without a fit.
  - *Left out of coverage*: G on a fit bound, the coating band on a bound, the coating band at zero height, counted apart.
  - *Ratios without a fit*: a straight baseline through 1030–1090 and 1700–1740 cm⁻¹, each height the mean of 7 channels at the band's median fitted position, its error channel noise (successive channel differences in 1700–1790 cm⁻¹) with baseline variation (the spread of the residual at 1765 cm⁻¹, where no band lies). The fitted D1/G must rank the spectra as the fit-free D1/G does (Spearman ρ; below 0.3 is flagged, below 0 suggests an inverted ratio), and the spread the fit adds of its own is reported (robust CV). A weak band such as D3 sits on the tails of D1 and G, so its fit-free height also follows D1/G; that is measured, and the fit-free D3/G is not used to judge the fitted one. On a 4 575-particle project: D1/G ρ 0.74, the fit adding 13 % of spread; the fit-free D3 height followed D1/G at ρ 0.61.
  - *ParticleFinder runs*: spectra accepted over particles located; where a run stopped early, the measured particles' positions against all selected ones (Kolmogorov–Smirnov on X and Y, and the share in the left half); whether the particle list runs across the field (rank correlation of list order with X and Y), which makes a stopped run a biased one; and what the run's own filter removed below the smallest and above the largest size it kept. On a 364-particle project that stopped after 83 particles, 97 % of those measured off the seams lay in the left half against 54 % of those selected. On a 4 575-particle project the filter kept 2.0 to 5.0 µm and removed 208 larger objects.
  - *Dispersion* (ParticleFinder): over the located particles, in the field the mosaic images, the distance from each particle to its nearest neighbour (centre to centre), the Clark-Evans ratio (the mean nearest-neighbour distance over 0.5 / √density: about 1 for particles dropped at random, below 1 when they clump, up to 2.15 for a regular lattice; no edge correction, so it reads a little high), the share touching a neighbour (equivalent circles overlapping), the share so large (over 3 × the median area) that they are likely touching particles segmented as one, and the share that is either (*crowded*). On the 4 575-particle project: Clark-Evans 0.83, nearest neighbour 56 µm (median), 3.9 % of the 410 located particles crowded. Above the limit under Acceptance, the check says to redisperse the powder.
- **Cross-checks on the map** (Particles tab, gridded maps, run on demand). Two estimates that use no band fit's ratio; they check the coverage and the within-particle variation and replace neither.
  - *Decomposition*: the particle pixels' spectra, a straight baseline through 1030–1090 and 1700–1740 cm⁻¹ taken off and 1100–1700 cm⁻¹ binned to 8 cm⁻¹, are split by non-negative matrix factorisation (hierarchical alternating least squares, Cichocki and Phan 2009) into 3 components, started from the mean spectra of the fifth of pixels with the lowest and the fifth with the highest fitted ratio and a flat one, so the result is the same every time. The coating-like component is the one with a G band and the most signal in the D3 valley; each pixel's share of it is compared with the fitted ratio (Spearman ρ). With an uncoated reference open and the floor set, the reference's spectra above the floor are projected on the same components, the 99th percentile of their share is the threshold, and every judged pixel is called coated or not both ways: the share of agreement, Cohen's κ, coverage per particle. *Colour pixels: by the decomposition* maps where the two calls agree and where they do not. On a coated map against an uncoated reference of the same session: a coating-like share of 9.4 % (median), ρ 0.58 with the fitted D3/G, 98 % coated both ways, agreeing on 98 % of 1 042 judged pixels (κ 0.32, low because nearly every pixel is coated). The coating-like component was absent from at least 99 % of the reference's spectra, so any share above 0 counted.
  - *Gaussian splats*: the coating band and G maps are each represented by up to 64 anisotropic 2-D Gaussians (a port of the splatting used for the coating maps: Adam on the analytic gradient, amplitudes by least squares, splats added where the residual is largest), fitted to 80 % of the particle pixels (at most 4 000) and scored on the other 20 %, against the pixel noise from neighbouring training pixels and a 1-pixel Gaussian smoother. The splats' amplitude-weighted median radius gives the spatial scale; the splat ratio field's robust CV inside each particle is set against the excess CV from the pixels. *Colour pixels: by the splat ratio field* shows it. Coverage is never taken from the splat field: it fills gaps smaller than its splats and cannot rescue weak signal. On the same coated map: held-out D3 1.08 counts against a noise of 0.96 (G 6.7 against 5.7), so the splats miss no structure; D3 varies on a scale of 2.6 µm; the splat ratio field's CV of 18 % against an excess CV of 12 %. The fit takes some seconds a band and yields to the page as it goes.
- **Between maps** (Particles tab, gridded maps). Each map's coating analysis is kept when it is drawn (the latest per open file), and every map analysed with the same coating band and rim is listed with an editable sample label (a first guess from the file name: the part before the first underscore, less a replicate number such as "-2"). Pixels of one map are not independent, so samples are compared through what does not pretend they are:
  - *Shape distance*: the Kolmogorov–Smirnov distance between every pair of maps, on the coating index divided by each map's median (the shape of the spread, not its level). The gap between samples is the mean distance between maps of different samples minus the mean between replicates, judged against 4 999 relabellings of the maps. With few maps there are few distinct groupings, and the check says how low p could go at all.
  - *Replicates by pixel*: KS p-values between replicate maps counting every pixel, and at each map's effective number of independent pixels, so the difference a pixel count manufactures can be seen.
  - *Uniformity by sample*: the particles' excess CVs (each particle with 100 pixels or more is one value) by Kruskal–Wallis (exact chi-square tail), beside a Brown–Forsythe test of the pooled pixels' spread, which treats every pixel as an independent particle.
  - On two replicate maps of one sample and two maps of two others: KS 0.11 between the replicates, 0.18 between samples, relabelling p 0.32 (no lower than 0.17 with 4 maps: 6 groupings); the particles' excess CVs, Kruskal–Wallis p 0.053 over 7 particles, against p < 0.001 from the 12 471 pooled pixels.
- **Acquisition record** (Particles tab). The settings LabSpec saves with the spectra are read from the file (both readers, pair for pair): exposure, accumulations, range, objective, grating, filters, laser, slit, hole, autofocus, spike filter and the rest, and the calibration's time stamp. *Use as the method* keeps one file's settings as the written method; every later file is compared setting by setting, and the differences listed. Position, times, detector temperature and labels change by nature and are not compared. A calibration is accepted when it is from the same day as the acquisition and before it; the file holds its time stamp, not the calibration spectrum, so the height of the silicon band cannot be checked. *Save method file* writes the method and the acceptance limits as JSON; *Load method…* reads one back. A ParticleFinder project that saved only its camera's settings has no acquisition record to check.
- **Acceptance** (Particles tab). Limits fixed before measuring: coverage (the level under Coverage), the between-particle CV, the within-particle CV and, for ParticleFinder runs, the share of located particles with an accepted spectrum, the share crowded on the slide (see *Dispersion*) and a lower limit on the coating index of the thinnest 5 % (judged on the lower end of its interval). Each criterion is judged on the bound of its 95 % interval: the certified coverage (with left-out spectra counted as uncoated), the lowest particle's area-coverage bound, the upper limit of the between-particle CV (Paule-Mandel) and the highest particle's upper limit of the within-particle excess CV (8 × 8 block resampling). The decision is *rejected* when any criterion fails; criteria a file cannot test are named (within-particle variation needs maps, particle-level coverage a population run, and thickness calibration films of known thickness, so a file is never accepted outright). Limits changed after a file was opened are flagged: a decision holds only on limits fixed before the data were seen. *How many to measure*: from SE² = CV_b² / n + (CV_w² + CV_n²) / (n k), the particles (one spectrum each) or maps (k independent pixels each) for a chosen standard error of the mean, never fewer maps than (CV_b / SE)², and the particles that certify the coverage level. *To tell two samples apart* (80 % power, 5 % two-sided): per sample, 2 ((z(0.975) + z(0.8)) CV / difference)² particles or maps for a chosen difference in the mean (CV per particle or per map from the variance components; a map's needs the between-particle CV, so 3 or more particles), and 1 + ((z(0.975) + z(0.8)) / ln ratio)² particles for a chosen ratio of spreads, from the error of a log variance ratio. On the 4 575-particle project: 452 particles per sample for a 10 % difference in the mean, 49 for a 1.5 × spread.
- **Splat 3D tab** (desktop version; a work in progress in the web app). Spectral Gaussian splatting: the baseline-corrected cube on the particles becomes a field of 3-D Gaussians in (x, y, Raman shift), fitted with `ramansp.splatting`. The WebGL viewer projects each Gaussian as in 3D Gaussian splatting. Every 5th channel is held out; on a 9 000-point map the held-out error is 0.97× the map's own noise, with 1 568 Gaussians and 58× fewer numbers than the cube.
- **Zoom.** Scroll on any map to zoom at the pointer, drag to pan, double-click (or ⟲) for the whole map. The four maps zoom together and the optical image follows; on ParticleFinder data each particle shows its number once you are close enough to read it.
- **Small windows.** Below 680 px of height the page scrolls (the top bar stays) rather than squeeze the maps and spectra.
- **Map grid.** The map cards are as tall as the map needs, so a wide map leaves no empty band. The four maps sit in a row as in Q-Carbon, or 2 × 2 when that draws each map at least 1.5 times bigger (wide maps on a laptop screen: about four times). Map tools (display options, PNG, enlarge) appear over the map on hover.
- **Several files.** Drop or pick several maps at once (each `.l6v` goes to the map whose name it shares most of; a ParticleFinder `.l6pf` goes with the spectra list named after it) and they are fitted one after another with the Carbon fit settings. The *Files* tab lists every map opened in the session with its status and a summary of the valid points (ratio median, mean ± SD), exports that summary as one CSV row per file, and shows the same map (ratio, band intensity or error) of up to four ticked files side by side on one colour scale. A file fitted with other settings is marked *settings changed*; *Fit all* refits only those. Click a file, or use the file menu in the top bar, to open it on the Carbon fit tab: its fit is reused when the settings still match. Fitted-result tables still open one at a time. In the web version fits run one at a time (they share the worker pool), and *Remove* frees the file's memory.
- **Display.** Colour maps: Viridis by default (even steps in brightness, so equal value steps look equal), with the LabSpec rainbow, Inferno, Magma, Turbo, Cividis and others in each map's ⚙ menu. Also 1–99 % / full / manual scaling, optional smoothing (display only; statistics always use raw pixels), enlarged map view and PNG export. The scale bar sits above the map so it never covers data, colour bars carry at least three labels, and the pinned crosshair is dashed and light. On narrow map cards (four across), the titles shrink to fit.
- **Report** (Report tab, then Print / Save as PDF). It leads with the results, then the maps, spectra, quality and configuration as before:
  - *At a glance*: the calibrated D3/G with its interval, how it compares with the uncoated reference, how many particles (or how much area) carry the coating, and the uniformity verdict.
  - *Particles covered by the coating* (ParticleFinder): how many of the particles judged have more D3 than the uncoated reference (D3/G above the level only 1 % of its spectra exceed), the share, and "at least" that share with 95 % confidence, counting particles that could not be judged as uncoated; one bar shows the particles coated, not coated, not judgeable and too weak to judge. *Area covered by the coating* (maps): the coated area in µm² and as a share of the particle area judged, per particle (a bar with its range and 95 % lower bound) and in all.
  - *Calibrated D3/G*: the median, its comparison with the uncoated reference and the band shapes held.
  - *Statistical analysis: summary*: a few plain questions with their answers: how much amorphous carbon, more than uncoated or not, how many particles (or how much area) are coated, whether the coating is the same everywhere, the thinnest particles against the uncoated level, size, and anything to check. Every test behind them stays in the Particles tab.
  - The Particles tab's analyses run first if the tab has not been opened on the file. Coverage needs an uncoated reference (or a threshold τ) under Coverage; without one the report says so rather than inventing a number. Charts are inline SVG for white paper; the report stays in Times New Roman.

**D3: shapes from the mean spectrum.**

- **Problem.** Fitted freely per pixel, the broad D3 band wandered to its bounds: on map B, 62 % of pixels had D3's position on a limit. It then soaked up background curvature the quadratic baseline cannot follow, so the D3 map showed the substrate, not the carbon. It correlated with Q-Carbon's own `D3(ar).l6i` at only r = 0.38, and the particle was not visible.
- **What the app does.** It first fits the mean spectrum of the carbon pixels. A band whose position or width a single pixel cannot determine keeps that mean shape, and only its intensity is fitted per pixel. "Cannot determine" means: standard error at the map's own noise level above ¼ of the width (or ½ of the width for the position).
- **Effect.** The particle is visible again, and map B's D3 correlates with Q-Carbon at r = 0.72. G is unchanged: it stays free, and still matches Q-Carbon at r = 0.9999.
- **Which bands are held** is decided per map, and the app says which under the Peaks table. Typically D3 and D4, plus D2 on noisier maps.
- **Limits.** A single pixel carries D3 at only about 1–2 σ at typical count levels, so some speckle is physics. D3 values left on bare substrate are background, not carbon: use *Exclude substrate (Otsu)*. A higher baseline order does not help (order 4 makes D3 worse).
- **Turning it off** gives the plain per-pixel fit. Q-Carbon itself sets D3 to zero in 38 % of map A's pixels. Compare D3 numbers like-for-like only, and not between programs.

**ParticleFinder format.** A `.l6pf` holds the mosaic (uint8 RGB with its X and Y stage axes), the spectra (one per particle, with a 1…P index axis) and a particle table of 24 float32 per particle: X, Y, area, circle-equivalent diameter, …, Feret max (field 10), min diameter (Feret min, 11), convexity (15), elongation (16), volume (18), bounding box (19–22), class (23). The table is found by an identity that cannot hold by chance, diameter = √(4 · area / π), and every position must lie inside its own box. Some versions do not tag the mosaic as a matrix. It then fills the gap between two records exactly, as on all 16 ParticleFinder projects on disk, and is read from there. Before, a search by smoothness looked for it, but that search cannot tell whole-pixel shifts apart: it placed six such mosaics 3 to 260 pixels off (0.6 to 250 µm). On one project, only 13 % of particle centres fell on a particle in the image (11 % by chance); read from the gap, 96 % do. Feret max sits where LabSpec's Results table lists it, just before Feret min, and behaves as a caliper length: on all 4 575 particles of a project it is never shorter than the box's longer side nor longer than its diagonal (within one mosaic pixel). Fields not pinned against the instrument are not shown.

**ParticleFinder status and seams.** Field 23 of the particle table is the particle's status: 0 excluded by the run's filter, 1 measured, 2 selected but not measured. Status 2 matches the all-zero spectra exactly (281 of 281, 75 of 75 and 89 of 89 on three projects). Seams are found on the full-resolution mosaic: a column (or row) whose median R+G+B lies 30 below the running median of the 41 lines around it, widened by one line. An object is on a seam when its centre is within a pixel of one, or when it runs along one (within 15 degrees, at least 2.5 times longer than wide) and the seam passes within half its width. On two stitched mosaics this finds 98 of 102 and 83 of 84 objects found on the seams from each object's own pixels, with 3 and 1 others.

**Particle shapes.** The table holds no angle. A particle's tilt comes from its Feret length and width and its box: an ellipse with those axes, tilted by t, has a box with half sides √(a² cos² t + b² sin² t) and √(a² sin² t + b² cos² t), which gives the size of t. The direction it leans (/ or \\) comes from the mosaic: the sign of the x–y covariance of the box's pixels, each weighted by how far it is from the background around the box. Both readers compute it with integer sums from the full-resolution mosaic and agree on every particle. On the large particles of one project, the direction follows the elongated features visible in the image. On another, the outlines match the particles' outlines in the mosaic, tilt included. For particles only one or two mosaic pixels across, the direction is a guess. Particles whose length is under 1.05 × their width are drawn without a tilt. The shapes are LabSpec's own measurements, so they outline what ParticleFinder detected: on that project, many detected particles were bright patches on larger dark grains, and the optical image shows the grain around them.

**Map orientation.** LabSpec rasters X fast and draws Y downwards, and its text export writes the Y column first. Reading the slow axis as X transposes the map: statistics are unaffected, but images and overlays are not. Both readers here follow LabSpec's convention.

## Conventions that could not be read off Q-Carbon

- The intensity constraint applies to the larger of the two ratio bands' intensities.
- A ratio with a zero denominator is 0 (the vendor exports do this).
- An unticked Fit box holds that band's position and width; its intensity is still fitted.
- *Skip fitting step* holds every position and width; intensities and baseline are still fitted.
- Red. χ² uses Poisson variance, max(model, 1). Q-Carbon's definition is not documented.
- LabSpec's own `.ini` files are not read. Configurations are saved in this app's format.
